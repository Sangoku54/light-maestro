# 2026-11-20 — Release 1.0.45 (LWS) + 4 bugs d'auto-update corrigés

## Contexte

Session de finalisation de la release **1.0.45** : bugs vue 3D / plugin Target
corrigés, build NSIS + portable produit, mise en ligne sur l'hébergeur LWS
(`https://light-maestro.com/download/`).

## Décisions structurantes

- **Auto-update LWS via `electron-updater` provider `generic`**, pas GitHub.
  GitHub reste le dépôt de code / release de artefacts, mais le serveur de MAJ
  est l'hébergeur LWS.
- **Domaine réel** : `https://light-maestro.com/download/` (cohérent avec le
  site vitrine + l'API license). Le placeholder `ton-domaine.lws.to` est
  INTERDIT.
- **Noms d'artefacts sans espaces** (`Light-Maestro-Setup-1.0.45.exe`) —
  electron-builder transformait les espaces en tirets pour GitHub, ce qui
  faisait pointer `latest.yml` vers un fichier fantôme (404 au download).
- **`build.publish` : `generic` en PREMIER** — `app-update.yml` embarqué est
  écrit depuis `publishConfigs[0]`.

## 4 bugs trouvés en vérifiant (et corrigés)

1. `latest.yml` référençait `Light-Maestro-Setup-1.0.45.exe` alors que le
   disque contenait `Light Maestro Setup 1.0.45.exe` → auto-update en 404.
2. `app-update.yml` embarqué = `provider: github` (écrasé à chaque build par
   electron-builder) → l'app cherchait les MAJ sur GitHub, pas LWS.
3. URL placeholder `ton-domaine.lws.to` jamais remplacée.
4. `mountGroundTipText` : j'avais inversé « vers le haut » → « vers le bas »
   sur la foi d'une note antérieure, sans vérifier le moteur. Faux :
   `clampTiltZone` impose `ground → élévation [0°, +90°]`. Texte rétabli.

## Leçon structurelle : ne pas donner d'instructions d'upload "au large"

J'ai dit « copie tout le dossier `site/` » alors que seuls **2 fichiers** avaient
changé depuis le dernier upload. L'utilisateur a uploadé des dizaines de
fichiers pour rien.

**Règle** : toujours mesurer avant de lister —
`git diff --stat <commit-du-dernier-upload> HEAD -- site/`.
Le résultat EST la liste d'upload.

## Contrôle position par position (demande utilisateur)

Demande : « confirmer position par position des fixtures sur scène, la direction
des faisceaux par défaut dans la vue 3D, et évidemment en réel DMX ».

**Méthode** (2 sondes, tout le code de production, zéro réimplémentation) :
- `src/__tests__/fixture-placement-default-probe.test.ts` : grille 6×6 de
  `initFixturePosition` → vérifie la convention « vue audience » (rear→public,
  hanging→public, ground devant→arrière, ground sur les côtés→centre).
- `src/__tests__/yolo-fixture-pose-probe.test.ts` : projet réel `LM/Yolo.lmproj`
  (9 fixtures patchées, scène 10×6 m) → 3 vues comparées (3D / DMX écrit /
  physique).

**Modèle physique retenu** (important, contredit un ancien commentaire) :
`pos.tilt` (tare statique) ET `pos.zeroPan`/`pos.zeroTilt` (tare zéro) sont des
tares **PHYSIQUES** (offset du zéro mécanique du moteur), pas cosmétiques.
Preuve : `clampPanZoneDmx` déduit ses bornes de `zeroPan`. L'i18n dit
« réglage visuel » → libellé à corriger si l'on veut lever l'ambiguïté.

**3 bugs trouvés et corrigés** :
1. `clampPanZoneDmx`/`clampTiltZoneDmx` **bypassés** quand la fixture a un
   centre capturé (`centerPan`/`centerTilt` ≠ 0) → le matériel sortait de la
   zone alors que la 3D clampe : écart mesuré **58,3°** (TONIO Mini #2).
2. Branche « repos » (amplitude 0) : le tick live n'appliquait **aucun** clamp
   de zone → une fixture au sol capturée visait le sol ; la 3D montrait un
   faisceau horizontal : écart **89,6°** (Stage Wash #3).
3. `computeDmxForCue` (matérialisation preset) écrivait **128/128 en dur** au
   repos, sans centre capturé ni zone → le preset matérialisé ne reproduisait
   pas le live.

**Correctifs** (`src/hooks/dmx-playback.ts`, `src/views/Stage3D.tsx`) :
- clamps de zone appliqués **toujours** (tick live + matérialisation), y compris
  centre capturé et branche repos ;
- la branche repos écrit le centre capturé + la zone (parité live/preset) ;
- la 3D ne clampe plus quand `hasManualTarget(id) || hasSceneAim(id)` (le
  moteur `applyAimTarget` écrit hors zone par design) ;
- `Math.round` sur toute écriture DMX issue d'un clamp (la trame `Uint8Array`
  tronque les floats : 223,83 → 223 = 0,6° sous l'horizon).

**Résultat** : écart max 3D/matériel = **0.00°** sur les 6 fixtures motorisées,
en mouvement ET au repos. `npm run check` : **974/974** verts (112 fichiers).
